### WebGlSceneRenderer

`sealed class WebGlSceneRenderer : ISceneRenderer, IDisposable`

`ISceneRenderer` backed by WebGL 2 through synchronous JS interop (Blazor WebAssembly).

Binary data goes to JavaScript as base64 little-endian float/uint32 buffers: meshes once per mesh-library version, instance data only when `RenderFrame.SceneVersion` changes. Per frame, only ~63 floats of camera/lighting/time uniforms cross the boundary; waves, bobbing and pulses animate on the GPU.

### IMarinaVisualizer

`interface IMarinaVisualizer`

The API the host application (typically an ERP) uses to drive the 3D marina: layout, slip status, selection, tooltips and actions, camera and appearance. It is UI-framework and graphics-API agnostic: the same instance drives the WinForms/OpenGL view (`MarinaViewControl`) and the Blazor/WebGL view (`<MarinaView>`).

Threading. Not thread-safe. Call it from the UI thread that owns the view (marshal with `Control.BeginInvoke` in WinForms or `InvokeAsync` in Blazor when data arrives on a background thread). Events. Raised synchronously on the calling thread, after the state change has been applied, so handlers can read the new state and call back into the API. Snapshots. `Slip`, `Dock`, `Boat`, `Divider` and `MultiSlipBerth` are immutable records. Getters and events return snapshots; change state only through this API. The exception is `Slip.ExternalData`, a mutable bag for host data shared by all snapshots of a slip. Ids of docks, slips, dividers and berths are compared case-insensitively.

### MultiSlipBerth

<a id="iscenerenderer"></a>
### ISceneRenderer

`interface ISceneRenderer : IDisposable`

The only contract a graphics backend must implement. The core library works out what to draw (`RenderFrame`); a backend (desktop OpenGL, WebGL, and later Vulkan, WebGPU, etc.) decides how.

Backend responsibilities: Upload every mesh in `RenderFrame.Meshes` (by id) and re-upload when `RenderFrame.MeshLibraryVersion` changes. Draw opaque objects, then the water grid with the water shader, then transparent objects with blending and depth writes off. Apply the frame uniforms (camera, lighting, water, time) to the shaders in `ShaderSources`. All calls happen on the thread that owns the graphics context.

| `protected override void OnPaint(PaintEventArgs e)` | In the designer (or if OpenGL is unavailable) draws a placeholder describing the 3D render area. |
